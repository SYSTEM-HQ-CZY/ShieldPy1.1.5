# 玄盾卫士 ShieldPy v1.1.5 · 虚拟机测试指南

> 适用对象：在 VMware / VirtualBox / QEMU 虚拟机中验证 v1.1.5 修复与新增功能。
> 建议：**每完成一项高风险测试就打一个虚拟机快照**，尤其是"高级清除"与"原地锁定"。
> v1.1.0 的全部功能请按下面第三~十三章继续回归，本版新增「第零章：五项重点验证」。

---

## 零、v1.1.5 五项重点验证（建议先跑这一章）

### 0.1 向导不再黑屏卡死（对应需求 1）

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| 1 | 首次运行（先删掉 `data\config.json` 或设置页点"重新运行初次向导"） | 弹出向导窗口，**首帧就有"⏳ 正在启动向导…"占位**，随后正常显示欢迎页 |
| 2 | 连点"下一步" 3 次（每步停 1 秒观察） | 每步都显示完整内容（模块勾选 / 处置策略 / 性能档位），**不出现空白或黑屏** |
| 3 | 切步瞬间观察 | 短暂出现"⏳ 正在准备下一步…"占位，然后内容出现 |
| 4 | 快速狂点"下一步" 10 次 | 不卡死、不重复叠控件，进度按 4 步走完就停在完成页 |
| 5 | 点标题栏 ✕ / 按 Esc / 点底部"关闭" | **三种方式都能立刻关闭**（关闭按当前/默认配置完成向导，下次启动不再弹） |
| 6 | 完成页勾选"立即创建第一份防勒索快照"→ 点"开始使用" | 显示"正在创建快照…（大文件较多时需要几十秒）"，**界面不假死**，完成后自动进主界面 |

> 历史根因已修复：v1.1.0 的向导把 `progress_color` 传给 `CTkCheckBox/CTkRadioButton`
> （customtkinter 6.0.0 不支持该参数），每步渲染必崩 → 黑屏 + 按钮无响应。
> 若仍复现黑屏，请把 `data\logs\shieldpy.log` 里 `向导渲染异常` 那段发回。

### 0.2 误报治理（对应需求 2）

| 步骤 | 操作 | 期望结果 |
|---|---|---|
| 1 | 在桌面建 `test.log`，写入 20 行含 `your files have been encrypted` 等勒索关键词的普通日志，然后扫描桌面 | **不应判为威胁**；日志里会出现 `[评分豁免] … 减免=['log_baseline']` |
| 2 | 找任意**有数字签名**的正常程序（如 `D:\python\python.exe` 之类）扫描 | 若被特征命中，日志显示 `减免=['signed']`，最终不判威胁（或降级为提示） |
| 3 | 建一个只有"可疑扩展名"的文件（如 `abc.hta` 内容为普通文本） | 只出"提示（提示级）"，**不弹高危病毒** |
| 4 | 把恶意脚本（含 `CreateObject("WScript.Shell")` + `powershell -EncodedCommand` + `MSXML2.XMLHTTP`）保存为 `drop.vbs` 放 **%TEMP%** | **仍应判高危**（脚本/可执行扩展名不享受日志基线减免） |
| 5 | 扫描结果表观察"评分"列 | 显示该条目的加权评分（如 171），便于判断是否误报 |

> 判威胁阈值默认 60 分（可在 `data\config.json` 里改 `risk_threshold`）。
> 想关掉减免做对照：`signature_check=false`、`log_baseline=false`。

## 二、初次启动向导（v1.1.0 新增）

1. 首次启动应**自动弹出**向导窗口（4 步）：
   - 步骤 1 欢迎页
   - 步骤 2 防护模块勾选（6 项，其中"高级清除"默认关闭）
   - 步骤 3 默认处置策略（隔离 / 删除 / 高级清除）
   - 步骤 4 性能档位 + 性能日志 + 立即创建第一份防勒索快照
2. 勾选"高级清除"时**必须弹出高风险确认框**，点"否"则自动取消勾选。
3. 点"开始使用"后写入配置，下次启动不再弹向导。
4. 想重测向导：设置页 → "重新运行初次向导" → 退出程序再启动。

## 三、扫描四种模式

| 模式 | 入口 | 期望结果 |
|---|---|---|
| 快速扫描 | 扫描页 / 仪表盘"快速扫描" | 只扫常用目录（Windows、System32、Temp、启动目录），速度明显快于全盘 |
| 全盘扫描 | 扫描页 / 仪表盘"全盘扫描" | 遍历所有**固定磁盘**；进度条**只增不减**（历史 bug 已修复） |
| 可移动驱动器 | 扫描页 / 仪表盘 | 仅扫描 `DRIVE_REMOVABLE` 类型（U 盘/移动硬盘）；插入 U 盘后才可用，无 U 盘时提示"当前没有可移动驱动器" |
| 后台低优先级扫描 | 扫描页 / 仪表盘 | 扫描进程优先级降到 IDLE，机器不卡；任务管理器里 `ShieldPy.exe` 优先级显示"低" |

**进度条验证要点**：观察前 30 秒，百分比不得出现"5% → 70% → 8%"这类回跳；出现即视为回归。

**性能档位验证**：设置页切换"低占用 / 均衡 / 高速"，分别在任务管理器观察 CPU：
- 低占用：单核 20% 以内
- 均衡：单核 40% 以内
- 高速：允许更高，但不得超过 70%（v1.0.2 遗留指标）

## 四、威胁处置链路（v1.1.0 重点）

准备测试样本（**只在虚拟机内使用**）：
- EICAR 测试串文件（安全、无危害，用于验证检测与处置链路）
- 一个"会被进程占用"的普通文件（复制一份大文件，用记事本或另一程序打开）

### 三档处置对比

| 档位 | 操作 | 期望结果 |
|---|---|---|
| 隔离（默认） | 扫描页底部选"隔离"，勾选结果 → 隔离选中 | 文件从原位置消失 → 出现在"隔离区"页 → 可"恢复选中"还原到原路径 |
| 删除 | 选中档位"删除" → 删除选中 | 弹确认框 → 文件被删除 → 同时清理相关启动项/服务/注册表残留 |
| 高级清除 | 选中"高级清除" → 处置 | **首次必须红字风险确认框**；确认后调用 `NSudoLC.exe` 以 TrustedInstaller 权限强制删除；操作记录写入 `data\advanced_clear.log`；日志页"查看高级清除日志"能看到本次记录 |

### 链路完整性验证
1. **进程终止**：先用某程序占用可疑文件，再执行处置 → 进程被结束（含子进程），随后文件被删除。
2. **占用文件兜底**：让文件被系统进程占用（如正在运行的 exe）→ 删除失败后应提示"已登记重启后删除"，重启后文件消失（PendMoves）。
3. **残留清理**：把一个样本的启动项（`HKCU\...\Run`）指向它，处置后该启动项应被清除。

> ⚠️ 高级清除必须连续测试 3 次，确认无蓝屏、无残留进程、日志齐全。

## 五、信任项（路径 + SHA256 双哈希）

1. 扫描页 → 选中条目 → "信任选中" → 弹确认框说明"文件内容被篡改后信任自动失效"。
2. 设置页"信任项"列表出现该文件，标记 `✓`。
3. **篡改验证**：用记事本给被信任文件追加一个字符（内容变化）→ 回到设置页点"校验全部信任项" → 该项变 `✕ 失效`，再次扫描该文件时会被重新检出。
4. 移除信任项后，扫描立即恢复检出。

## 六、原地锁定（v1.1.0 新增）

> 目的：可疑文件"只许存在、不许运行"（双击才运行的木马）。

1. 扫描页 → 选中来自**用户目录**的条目 → "原地锁定" → 弹确认框。
2. 成功后"原地锁定"页出现记录（时间 / 路径 / 原始所有者 / 大小）。
3. **验证效果**：资源管理器双击该文件 → 应弹出"没有权限"或无法启动；文件仍在原位。
4. **验证权限**：`icacls "文件路径"` → 所有者显示 `NT AUTHORITY\SYSTEM`，ACL 中有 Everyone 拒绝执行的项。
5. **放行还原**：锁定页 → "放行（还原权限）" → 双击可正常运行，所有者恢复为原账户。
6. **系统目录拒绝**：对 `C:\Windows\System32\` 下文件执行锁定时，应直接提示"不可锁定（系统目录禁止）"。

## 七、受保护文件夹（受控文件夹访问）

1. 勒索防护页 → "受保护文件夹…" → 确认默认覆盖：文档 / 桌面 / 图片 / 视频 / 下载。
2. **批量篡改模拟**：在受保护目录里快速创建/改写 20+ 个文件（可用批处理 `for /l %i in (1,1,30) do echo x > test_%i.txt`）。
3. 期望：达到阈值（默认 10 秒内 20 次）后**弹窗告警**，说明目录、次数、涉及进程。
4. **行为边界**：不应结束发起操作的进程，不应隔离它 —— 只告警（这是设计约束）。
5. 可自定义增删受保护文件夹，保存后立即生效。

## 八、勒索防护（System Watcher + 快照回滚）

| 测试 | 操作 | 期望 |
|---|---|---|
| 加权打分 | 在受保护目录快速写入大量文件 + 执行带勒索扩展名的改名 | "勒索防护"页评分上升，超过阈值（默认 60）弹出高危告警 |
| 命令行特征 | 用 `powershell -enc <base64>` 启动一个无害脚本 | System Watcher 记录"可疑命令行"事件并计分 |
| VSS 删除监控 | `vssadmin delete shadows /all /quiet`（虚拟机内安全） | 监控到卷影副本数量减少 → 高危告警（评分 +75） |
| 快照创建 | "立即创建快照" | 快照列表新增记录（时间/文件数/体积），可在 `data\snapshots\` 看到 manifest.json |
| 回滚 | 修改若干已快照文件（模拟加密），再"回滚选中快照" | 被改动文件恢复原内容；改动前版本另存 `rollback_backup\` 便于取证 |
| 只告警不动作 | 任意场景 | 程序不主动杀进程、不主动断网 |

## 九、界面规范验证（CustomTkinter 化）

1. **无原生标题栏**：窗口顶部是自制栏（♜ 图标 + 标题 + — / ▢ / ✕），无 Windows 自带的蓝/白标题栏。
2. **拖动**：按住顶部栏空白处拖动，窗口跟随移动。
3. **双击最大化**：双击顶部栏 → 全屏（高度自动扣除任务栏）；再双击 → 还原。
4. **圆角**：普通窗口四角为圆角；最大化后为直角。
5. **高 DPI**：125% / 150% 缩放下文字不发虚（程序启动时已 SetProcessDpiAwareness）。
6. **深浅色**：设置页切换主题 → 必须**弹窗提示"重启生效"**（历史卡死 bug 的修复方案）→ 退出重开生效。
7. **托盘常驻**：点 ✕ 后窗口消失但进程仍在（任务管理器可见）；托盘图标右键菜单：显示主界面 / 暂停·恢复实时防护 / 创建快照 / 退出；"暂停"后状态条与侧边栏变黄。
8. **侧边栏分组**：总览 / 扫描与查杀 / 防护模块 / 系统 四组十个入口，切换时当前项高亮为主色。

## 十、实时防护与四模式共存

1. 默认**全盘防护**（无需用户选文件夹）：设置页"监控范围"默认"全盘防护（推荐）"。
2. 往 `C:\`、`D:\` 根目录各拷一个 EICAR 测试文件 → 立即被拦截并按默认策略处置（隔离）。
3. 暂停防护后拷贝同样文件 → 不拦截；恢复防护后再次拷贝 → 拦截。
4. 自启动项监控：往 `HKCU\...\Run` 新增一项 → 防御中心记录"启动项新增"告警。
5. hosts 保护：修改 `C:\Windows\System32\drivers\etc\hosts` → 记录告警。

## 十一、已知限制（必须向使用者说明）

| 限制 | 说明 |
|---|---|
| 用户态监控延迟 | 无内核驱动，文件落地与拦截之间存在毫秒到秒级延迟，无法做到驱动级实时阻断 |
| 驱动级 Rootkit | 无法检测/清除，遇到疑似 Rootkit 请把磁盘挂到 PE 环境（Fir PE / DiskGenius）清理 |
| 高级清除依赖 NSudo | `NSudoLC.exe` 会被部分安全软件标记为风险工具；提权删除不可回滚 |
| 反网络攻击只告警 | 用户态无法接管防火墙，只做行为告警，不主动断网 |
| 原地锁定范围 | 仅用户目录；系统目录禁用（防止把系统文件锁死） |
| 受控文件夹只告警 | 不杀进程、不隔离程序，避免误伤正常批量操作（如解压、编译） |
| 未签名 exe | 未做代码签名，部分环境（如智能应用控制 SAC）会拦截运行，需手动放行 |

## 十二、故障排查

| 现象 | 排查 |
|---|---|
| 双击无反应 / 一闪而过 | 查看 `data\logs\startup_error.txt` 与 `data\logs\shieldpy.log` |
| 托盘图标不出现 | 确认 `pystray`、`Pillow` 已打包；用 `set SHIELDPY_NO_TRAY=1` 启动可绕过托盘直接看窗口 |
| 高级清除提示"未找到 NSudo" | 设置页填写 `NSudoLC.exe` 绝对路径，或确认 `tools\nsudo\NSudoLC.exe` 存在 |
| YARA 引擎不可用 | `data\yara\shieldpy_base.yar` 是否生成；模块页"引擎状态"会显示具体错误 |
| 主题切换无效 | 属预期：需退出重开（界面已提示） |
| 扫描卡死 | 点"停止"，再重新开始；日志会记录扫描模式与统计 |
